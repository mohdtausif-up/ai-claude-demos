Product Requirements Document: SSShare.com
1. Executive summary

This PRD proposes SSShare.com, a privacy-focused platform for sharing screenshots, images, text snippets, code, and lightweight files through temporary or controlled links. The product should preserve the speed and simplicity of imageupload.io, while expanding it into a broader, more polished sharing workspace with stronger privacy, richer expiration controls, screenshot annotation, text-to-image sharing, team collaboration, advanced analytics, APIs, and an exceptional mobile-first interface.

The proposed stack is:

Backend: PHP 8.1
Database: MySQL 8
Frontend: HTML5, modern CSS, JavaScript
Architecture: Server-rendered PHP enhanced with asynchronous JavaScript
Storage: Local storage during development, S3-compatible object storage in production
Workers: PHP CLI processes triggered through Supervisor or cron
Caching and queues: Redis recommended
Web server: Nginx with PHP-FPM
Image processing: Imagick, with GD as fallback

Research boundary: The competitive inventory below is based on publicly accessible pages and documentation available on October 6, 2026. It does not include private dashboard behavior that requires a paid account or features that have not been publicly documented.

2. Competitive analysis: imageupload.io
2.1 Uploading and file handling

The public uploader supports drag-and-drop, file selection, clipboard paste, batch upload and folder dropping. Publicly documented image formats include PNG, JPEG/JPG, WebP, GIF and AVIF. The free-plan upload limit is 25 MB, increasing to 50 MB on Pro and 100 MB on Business.

The service validates that an uploaded file can actually be decoded as an image. It normalizes orientation, removes embedded metadata and stores a processed result rather than blindly storing the original input.

Its documented upload output includes:

Human-readable share page
Direct image URL
HTML embed code
BBCode embed code
Markdown embed code
Image dimensions and MIME type in API responses
Expiration and password status
Current API quota information
2.2 Temporary-sharing controls

The platform has three main deletion models:

Fixed expiration: Free users can select one day, one week or one month. Starter adds longer or non-expiring storage, while Pro and Business support custom expiration dates.
Delete after view: The image is consumed after the first successful direct-image request.
View-limited sharing: The owner can select between 1 and 999 unique views. Repeated requests from the same browser fingerprint are deduplicated for 30 minutes, and the upload is deleted after 30 days if the view limit has not been reached.

Password protection can be combined with timed expiration, burn-after-view or view-limited sharing. The documented implementation protects both the share page and image-serving path until access is authorized.

2.3 Privacy and anonymous use

Anonymous uploads can be made without creating a user account when anonymous uploading is enabled. Anonymous uploads receive the same documented file validation, metadata removal, expiration and password options, but do not appear in a management dashboard. Users must save the returned links themselves.

The service explicitly states that “anonymous” refers to the absence of an attached account, not invisibility. IP addresses, browser data, fingerprints and security events may still be processed for rate limiting, abuse prevention, investigations and legal compliance.

EXIF metadata, GPS coordinates and camera information are removed during hosted-image processing. A separate browser-only EXIF tool can inspect and clean JPEG/JPG files locally without uploading them, with a documented limit of 25 MB and 40 megapixels.

2.4 Accounts, organization and management

Registered users receive dashboard-based management, storage quotas, folder organization and image management. Public galleries and custom short links are offered on eligible plans. Image-history duration is documented as 90 days for Pro and one year for Business.

The service provides:

Folder organization
Image listing
Individual-image inspection

Storage-quota display
View-count analytics
Referrer analytics
Country and device analytics on higher plans
Public galleries
Custom short links on Pro and Business
2.5 API and developer capabilities

A Bearer-authenticated REST API accepts multipart/form-data through POST /api/upload. It supports expiration mode, view limit, password, folder, custom slug and custom expiration date. Responses return structured URLs, embed snippets, image metadata, expiration details and quota information.

The API documents standard HTTP error handling for malformed input, authentication failure, unavailable plan features, moderation rejection, oversized files, unsupported types, rate limits, storage failures and overloaded processing queues. Successful responses include quota-used, quota-limit and quota-remaining headers.

An MCP server shares the same key and quota as the REST API. It supports image upload, image listing, metadata retrieval, deletion, folder listing, folder creation and quota checks for compatible AI tools. The public materials mention compatibility with tools such as Claude Desktop, Cursor and Windsurf.

2.6 Plans and limits

The documented plans are:

Free: 500 MB, 25 MB files, 10 API/MCP uploads monthly and expiration up to one month.
Starter: 5 GB, 25 MB files, 50 API/MCP uploads monthly, no-expiration option and basic analytics.
Pro: 50 GB, 50 MB files, unlimited API/MCP uploads, custom expiration dates, custom links, public galleries, full analytics and 90-day history.
Business: 500 GB, 100 MB files, unlimited API/MCP uploads, one-year history and dedicated support. Priority CDN and custom-domain support are marked as upcoming features.
3. Competitive gaps and SSShare opportunities

SSShare should not merely clone another uploader. Its differentiation should come from combining temporary media sharing, screenshot workflows, text sharing and controlled collaboration in one coherent product.

Key opportunities include:

Expiration measured in minutes and hours, not just days.
Text and code sharing, alongside images.
Screenshot annotation and automatic redaction.
Revocable recipient-specific access.
Encrypted uploads and optional zero-knowledge mode.
Approval, commenting and review workflows.
Link-level audit logs.
Flexible expiration using time, views, downloads and inactivity.
Automatic sensitive-data detection.
Versioning and replacement without changing the shared URL.
Workspace and team administration.
Custom branding and domains.
Regional storage and configurable retention.
Progressive Web App and browser-extension capture.
Webhook, REST API and command-line integrations.
4. Product vision
Vision statement

SSShare.com enables anyone to capture, protect, share and automatically remove visual or textual information in seconds.

Product principles
Fast by default: A screenshot should be shareable in fewer than five seconds.
Private by default: New uploads should start as unlisted and metadata-cleaned.
Controls before upload: Users should select access and expiration rules before sending data.
Clear lifecycle: The interface must explain exactly when and why content will disappear.
Reversible until deletion: Owners should be able to revoke, extend or replace an item while it remains active.
Accessible everywhere: The core experience must work on desktop, mobile and keyboard-only navigation.
No dark patterns: Expiration, billing and privacy behavior must be understandable.

9.3 Storage strategy

Binary objects should not be stored directly in MySQL. MySQL should hold metadata and object keys.

Recommended flow:

Upload to private temporary storage.
Verify actual MIME signature.
Scan for malware.
Decode and inspect image.
Strip metadata.
Generate required derivatives.
Move into private object storage.
Serve through an authorization endpoint or short-lived signed URL.
Delete original temporary data.
Queue expiration and cleanup events.

13. Privacy requirements
Strip EXIF and location metadata by default.
Never publicly index unlisted content.
Set noindex, nofollow, noarchive on non-public pages.
Allow owners to delete content immediately.
Publish clear deletion behavior.
Separate operational logs from analytics.
Minimize IP retention.
Offer analytics opt-out.
Allow data export and account deletion.
Provide configurable cookie consent where legally required.
Do not use uploaded content for model training without explicit, separate consent.
Make region and retention controls available to business customers.
Record deletion completion, without retaining deleted content.

An advanced “zero-knowledge share” mode can encrypt files in the browser using Web Crypto. The decryption key should remain in the URL fragment, which browsers do not send to the server. This mode must clearly explain that server-side preview generation, malware inspection, content moderation and recovery may be limited.

19. Acceptance criteria for MVP

The MVP is ready when:

A guest can paste a screenshot and receive a share URL without registration.
A user can choose expiration as short as one minute.
Password-protected files cannot be retrieved through an alternate direct URL.
Burn-after-view access is atomic under concurrent requests.
Metadata is removed and verified before storage.
Expired content is inaccessible and physically queued for deletion.
Owners can revoke links instantly.

The public share page meets WCAG 2.2 AA requirements.
Final recommendation

SSShare should position itself as“the fastest private sharing workspace for screenshots, text and temporary visual information”, rather than competing solely as another image host. The strongest early differentiators should be minute-level expiration, text and code sharing, a polished screenshot editor, automatic redaction suggestions, compound deletion rules and transparent access logs.

The PRD improves upon the researched product by broadening the supported content types, making access policies significantly more expressive, adding reviewer collaboration and treating deletion as a verifiable product capability rather than a background convenience. The design should remain simple at first glance, with advanced controls progressively disclosed so the additional power does not harm the quick-share experience.
